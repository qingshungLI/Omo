1. 通信拓扑：中心化编排模式

短版主管-执行者模式，子Agent只与主Agent通信，路径清晰可控。

长版最主流且可控的通信拓扑是中心化编排模式，即主管-执行者模式。一个主Agent居中调度，所有子Agent只与主Agent通信，子Agent之间不直接对话。主Agent负责拆解任务、分发、收集结果和汇总。这种模式通信路径清晰，全局状态由主Agent统一维护，不易混乱，且可观测、易调试。真实项目中除非有强理由，一般优先选择此模式。

概要页多Agent协作的第一步是选对通信拓扑。中心化编排模式是最主流且可控的方案：一个主Agent居中调度，所有子Agent只与主Agent通信。这种模式路径清晰、全局状态统一，易于调试和观测。掌握它，你就掌握了多Agent系统设计的基石。

2. 消息契约：结构化消息格式

短版Agent间用结构化消息固定目标、输出格式、工具、边界等，避免歧义。

长版消息契约是多Agent通信中最易被忽略但最关键的一环。Agent之间绝不能使用自然语言自由交流，否则会导致歧义和信息丢失。正确做法是使用结构化消息格式，将每次交互的内容固定下来，包括子任务的目标、期望输出格式、可用工具、边界条件以及上一步结果等。这相当于给Agent之间定一份接口协议，接收方获得的信息确定且可解析，交接时上下文不易断裂。Anthropic的研

概要页Agent之间通信不能靠自然语言自由发挥，否则歧义和上下文断裂在所难免。消息契约通过结构化格式固定目标、输出、工具和边界，相当于给Agent之间定了一份接口协议。学会设计它，你的多Agent系统才能可靠交接。

3. 共享状态：统一维护的公共黑板

短版通过共享结构化记忆区，所有Agent读写同一份真相，保持上下文干净。

长版共享状态解决如何让所有Agent看到同一份真相的问题。常见做法是设置一块共享的结构化记忆区，类似公共黑板，Agent将关键进度、中间结论和状态写入其中，需要时读取，而非靠消息互相追问。子Agent返回结果时只需将精简结论写入共享状态，主Agent读取，从而保持Agent上下文干净。共享状态必须由编排者统一维护，保证全局视图一致，防止信息错乱。

概要页多个Agent协作时，如何让它们看到同一份真相？共享状态管理通过公共黑板机制，让所有Agent读写统一的结构化记忆区，保持上下文干净。子Agent只需写入精简结论，主Agent统一维护全局视图。这是防止信息错乱的关键设计。
