# 视频 Provider Evaluation

这个目录用于记录抖音/小红书视频链路的 provider 评测。

评测目标不是追求单次 demo 效果最好，而是选择适合拾贝第一版产品默认链路的稳定组合：

1. TikHub 负责公开视频取源。
2. 平台字幕或 ASR 作为主证据。
3. OCR 和视觉摘要作为增强证据。
4. V2 出题系统只消费标准化后的 `LearningSource`，不绑定具体模型。

## 当前默认策略

- 主链路：TikHub -> 平台字幕/ASR -> timestamped LearningSource -> V2 出题。
- 增强链路：抽帧 -> OCR/VLM 视觉摘要 -> 合并进 LearningSource。
- 降级策略：OCR/VLM 失败不阻断出题，用户侧只显示抽象内容依据。

## 样本分层

每轮至少覆盖：

- 抖音知识讲解，主要靠口播。
- 抖音教程/录屏，画面里有 UI 或步骤文字。
- 小红书知识/设计视频，有平台字幕。
- 小红书视频，无可用平台字幕。
- 低信息量视频，预期触发内容不足或低质量结果。

## 指标

- TikHub 取源成功率。
- 平台字幕可用率。
- ASR 段落可读性。
- OCR/screen text 覆盖价值。
- VLM 视觉摘要是否增加可出题证据。
- `sourceSections` 是否适合用户查看原文。
- unit 数、题量、题目质量。
- TikHub 调用次数和成本。
- 模型 token 和估算成本。
- 失败是否可降级、是否用户可理解。

## 结论口径

默认 provider 只应在真实样本矩阵里同时满足以下条件后切换：

- 比 ASR-only 明显提升 source 覆盖或题目质量。
- 失败率和输出结构稳定性可接受。
- 成本不会超过产品可承受阈值。
- 失败时能无感降级到 transcript-only。
