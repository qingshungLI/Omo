# Recallo 视频取源与体积控制策略

更新日期：2026-07-23

## 目标

Recallo 不把“理解视频”实现成“先下载完整视频”。默认只获取生成可复习内容所需的最小证据，并明确告诉下游本次覆盖了字幕、音频还是画面。

## 分级链路

1. 只读元数据：标题、作者、时长、分 P、封面和可用字幕。
2. 平台字幕：有字幕时直接读取带时间戳的字幕，不下载视频或音频。
3. 音频降级：无字幕时只下载最低可用码率音频，转为 16 kHz 单声道后做 ASR。
4. 画面抽样：后续按章节或转写时间点获取少量关键帧，不以完整视频下载为前提。
5. 不能完整覆盖时，将结果标记为部分理解，不把抽样结果描述成整段视频结论。

## 默认阈值

| 项目 | 默认值 | 行为 |
| --- | ---: | --- |
| 视频时长 | 15 分钟 | 超过后不进入当前自动生成主链 |
| 完整媒体 | 40 MiB | 下载器在下载前或流式下载过程中阻断 |
| 音频 | 20 MiB | 超过后不继续完整音频 ASR |
| B 站无字幕视频 | 音频优先 | 不下载完整视频画面 |

阈值通过 `VIDEO_MAX_DURATION_SECONDS`、`VIDEO_MEDIA_MAX_BYTES` 和
`VIDEO_AUDIO_MAX_BYTES` 调整。

## 从 BiliGPT 借鉴与不借鉴的部分

借鉴：

- 通过 B 站 `view` 接口取得 `aid/cid` 和分 P；
- 通过 `player/v2` 取得字幕列表；
- 优先 `zh-CN`、`ai-zh` 等中文字幕；
- 保留时间戳，便于回到原视频证据位置。

不直接照搬：

- BiliGPT 旧版没有字幕时直接失败；Recallo 降级到音频 ASR；
- BiliGPT 为压缩 Prompt 随机丢弃字幕；Recallo 按时间顺序确定性分块，避免破坏证据连续性；
- Recallo 的目标不是摘要，而是生成一个有证据绑定的记忆点和复习题。

## 当前边界

- B 站链路已实现字幕优先和音频优先；
- 抖音、小红书仍沿用短视频媒体链，但受 40 MiB 硬上限保护；
- 关键帧按章节抽样尚未实现，因此音频优先结果会标记为未覆盖画面；
- 私有、付费、登录后可见或受版权限制的内容不绕过平台权限。
