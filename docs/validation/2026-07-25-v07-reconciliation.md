## 1. 当前继续冻结的合同

- 一份截图或内容默认生成一张主记忆卡；只有存在 2–3 个语义独立、分别可主动回忆且各自证据充分的高信息密度知识点时，才生成 2–3 张。不得按 OCR 字数或视频长度机械扩卡。
- `semantic_cloze`、`true_false`、`multiple_choice` 是每张 Evidence 卡的复现变式，不是把一道知识点拆成三张卡。
- 首页只显示“今日 / 知识库 / 我的”；一次只呈现一张，后台会话最多准备十张。
- 用户完成当前卡后主动选择继续或先收好，不强制十张、不自动连播。
- 同一 capture group 也只逐张召回；卡叠和 `1/N` 只表达同一内容含有多个独立记忆点。
- 持久化返回的 `captureGroup.index` 从 0 开始，`cardIds` 保持 canonical 顺序；每张卡独立调度、反馈和删除。
- 重复截图返回首次持久化的 canonical group，不覆盖原顺序、调度、掌握状态或已删除状态。
- `sourceContext` 使用 `capture_source_context_1` 正式 shape，由服务端从来源 block 和截图焦点确定性构建；答案揭示前只能通过“查看脉络并揭晓”显式进入同一揭晓流程。
- 首次召回以 26pt 自由路径擦开承重语义，45% 覆盖后完整揭示，并保留点击和无障碍等价入口。
- R / SR / SSR 是证据约束下确定性的知识核心潜力，与掌握状态和调度分离；没有随机概率、保底或付费抽取。
- 当前反馈继续使用“记得 / 模糊 / 忘记”三个按钮及现有后端枚举。本轮不改为三节点滑杆，也不顺带重写调度。
- `IP1-1.svg` 是唯一正式角色资产。英文角色名确定前，用户界面使用“记忆伙伴”或“它”；“毛球”只可作为内部造型说明。
- 学习与社交分开；知识图谱、创作者生态和公开挑战不进入当前 MVP。

## 2. 本次从 v0.7 草案吸收的内容

- 产品定义、目标用户和“从自己的过去召回一段记忆”的玩家幻想。
- Capture、Evidence、Memory Card、Recall Variant、Assessment、Schedule 的真值边界。
- 一次捕获与 1–3 张独立卡之间的 `captureGroup` 边界，以及 `memoryCard` / `schedule` 作为首卡兼容镜像的约束。
- “当前截图附近的内容”使用 overview、focus blocks、可选视频时间戳和 completeness，且不以模型改写替代来源 block。
- 来源未验证时进入记忆碎片、仅存档或需要确认，不伪造确定性知识。
- 大视频按元数据、字幕、局部片段、受限转写逐级处理，不默认完整下载。
- 恢复时保持同一卡、同一版本、同一稳定阶段和擦开状态，避免重复提交。
- Fixture、真实 HTTP、live 模型、Postgres、Xcode、Simulator 和无障碍必须分层报告，低层证据不能替代高层证据。
- 产品指标优先观察跨时间的合格二次唤醒，而不是截图数、SSR 数量或单次完成张数。

## 3. 本次明确不合入的扩展

以下内容有价值，但属于独立生产化纵切片：

- Share Extension 与 App Group 离线 outbox；
- 最多两个来源候选、只保存截图和内容级二次验证；
- 每日本地时间 20:30 的问题通知、时区处理和版本化深层链接；
- 服务端五秒删除撤销与数据库、内存存储一致性；
- worker 重启接管与 Postgres 并发恢复；
- 真实知识图谱、时间相册、高级筛选和 Shortcut。

这些能力未完成时不得对外宣称可用，但也不阻塞当前截图上传、逐张召回、擦开、自评和调度的可演示闭环。

## 4. 本次修正的实现差异

- iOS 首张召回统一为 1800ms，后续召回统一为 900ms；Reduce Motion 保持 180ms。Web 已使用相同节奏。
- Web 上传处理不再把内部阶段映射成 20/42/64/86% 的伪百分比，只展示服务端返回的真实阶段文案。
- Web 用户可见文案不再直接称角色为“毛球”，与 iOS 的中性命名一致。
- UI 回归守卫新增“无合成百分比”检查，并锁定 1800/900/180ms 三档时间合同。
- 后端 `capture_memory_card_2` 新增 `memoryCards` / `schedules` 数组，同时保留首卡 `memoryCard` / `schedule` 镜像；非 `create_card` 结果数组为空。
- Web 和 iOS 接收持久化后的 `captureGroup` 与 `sourceContext`；答案揭示前打开上下文会明确触发揭晓，揭示后才展示 overview 与焦点 block。
- 重复截图、独立反馈和单卡删除都以 canonical capture group 为边界，不把一个组当成同生共死的单条记录。

## 5. 仍需后续处理的真实差距

- iOS 知识库仍兼容展示旧章节资料；当前截图卡和记忆碎片是真实数据，但尚未完成旧章节的迁移或只读归档设计。
- iOS 的橄榄绿设计系统与 Web 的奶油白、珊瑚橙场景色仍有平台差异。本轮不以替换整套设计系统的方式解决，后续应先用同一页面做视觉 A/B，再冻结跨平台 token。
- 角色英文名尚未最终确定；代码和文档不得擅自把临时名称升级为产品名。
- live Qwen/TikHub、Postgres worker 恢复和真机 VoiceOver 仍需分别保留验证证据。
- 新增多卡与来源上下文不扩大本轮范围：不因此建设知识图谱、社交功能或新的平台 Adapter。
